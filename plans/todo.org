- [X] [[file:container-reconciliation.org][container-reconciliation.org]] —
  *COMPLETE 2026-10-13.* What happens to container content when the
  *destination* GeoPackage already has some. All six requirements built, in two
  passes the same day: § 3's set-union layer with § 5's refusals, then § 4's
  index construction. =src/geopackage/reconcile.rs= is the module, wired in
  =main.rs= — **the destination's container is merged rather than destroyed**,
  which clears =same-format-fidelity.org= M3b's last gate.

  A merge now dedupes the metadata pair by content, applies its id map to the
  references and dedupes those on the mapped values keeping the destination's
  stamp; set-unions tables and pyramids by name; and for a same-named **tile
  pyramid** unions the tiles on Requirement 54's key, reissuing the incoming
  side's rowids, ***building*** the index from the merged rows,
  recomputing =sqlite_sequence= behind them and *remapping* any row-scoped
  =gpkg_metadata_reference= to the tile it still means. Six refusals cover what
  has no union. /Measured: all **120** writing pairs across this tree's =.gpkg=
  fixtures produce files passing all three oracles; the other 36 refuse with a
  stated reason. For the built index the pragmas are **not** the test — a
  mis-sorted b-tree still holds one entry per row and passes =integrity_check=,
  so =sqlite_enforces_the_unique_behind_a_merged_pyramids_built_index= makes
  SQLite find a duplicate through it and refuse./

  *Three things worth keeping, none of them in the plan.* **§ 4 turned out
  cheap and D10's reversal is spent**: no producer emits an index this crate
  struggles with, so =compare_values='s =BINARY=-only scope stands and a
  =COLLATE=/=DESC= key is refused rather than approximated. **A built index is
  not byte-equal to a carried one** over identical rows — =encode_record=
  writes every integer as an 8-byte serial type where SQLite picks the
  narrowest — which is valid and worth knowing before anyone asserts byte
  equality against GDAL's output. And **two defects came out of § 3**,
  =handoff.org= entries 22 and 23, one of them reachable with no merge involved
  at all.

- [ ] [[file:kml-standard.org][kml-standard.org]] — M3's KML spoke, rescoped
  2026-10-22 to *the standard*: OGC KML 2.3 as a typed model in the KML native,
  both OGC versions (2.2, 2.3) read and detected, and =--kml-version= choosing
  the output, defaulting to the source's version on =kml -> kml= and to 2.2
  otherwise. Pre-OGC 2.0/2.1 are refused. Starts at K1 (a namespace-aware
  =xml.rs=). All eight open questions were decided on 2026-10-22 (D-K11 to
  D-K15).

  /2026-10-23:/ measured in Google Earth Web, GDAL LIBKML and CesiumJS. *A
  =GroundOverlay= turns on the ground*, which closes D-K14. *No reader measured
  reads 2.3's =kml:Track=*, while all three read =gx:Track=, so the default
  output from another format is now **2.2** (D-K2) and an explicit
  =--kml-version 2.3= writes the standard's spelling with no warning about
  readers (open question 9, decided). K5 builds the 2.2 writer first. The
  2.3 XSD 1.1 oracle runs under Python's =xmlschema= -- no JVM. See
  =kml-standard.org= § MEASURED IN A RENDERER and § ORACLES.

  /2026-10-23, later:/ ***K1 and K2 are built*** -- a namespace-aware
  =xml.rs=, applied to the reader at once; version detection from the 2.3
  schema's own assertions; Google's 2.0/2.1 refused; =--kml-version=; and the
  output's version resolved as D-K2 says, every write schema-valid. ***K3 is
  built too*** -- the document model, as an identified node tree over the
  whole 2.3 vocabulary (D-K4a), generated from the schema and round-tripping
  every fixture. ***K4's first step is built***: the reader parses into the
  model, each Placemark's element travels as its feature's native, and a
  =kml -> kml= run in the source's version gives the document back --
  styles, folders, overlays, models, tracks' times -- with the IR's edits
  applied. The schema oracle reads its =.xsd= files from a directory
  you supply, not from the tree.

  /2026-10-24:/ ***K4 is built.*** Ground and photo overlays are features
  (a footprint turned on the ground, a point, each with an =icon=); a
  feature's time is =timestamp=/=begin=/=end=; =<Schema>= types
  =<SimpleData>= and declares the columns, so KML now carries a column
  schema; and the altitude members are properties, with an all-=absolute=
  document read as EPSG:9707. Every write validates against both schemas.
  What remains is K5, the version writers: lowering to 2.2, then 2.3.

  /2026-10-28:/ ***K5's 2.2 writer is built.*** A 2.3 read written as 2.2 is

  /2026-10-28, later:/ ***K5 is built.*** A 2.2 document written as 2.3 is
