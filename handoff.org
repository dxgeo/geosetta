* Handoff -- Round-Trip Fidelity and Edit Composability

Orientation doc for an agent picking up the fidelity work started 2026-08-20.
Same role =geoscribe/handoff.org= plays for the CRS work: read this, then the
plans it points at.

*M1 and M2 are done; M3 has begun (FlatGeobuf).* Implemented: the natives
mechanism (=src/native.rs=) and the GeoJSON spoke, plus both of D1's modelled
fields -- =FeatureCollection::name= and the column schema (=FieldDecl= on
=FeatureCollection::schema=, populated and honoured by the Shapefile and
FlatGeobuf spokes). 487 tests pass (=cargo test -p geosetta=: 442 lib, 44
integration, 1 doc), clippy clean. The other seven spokes pass =native: None=
and carry no declaration; they lose exactly what they lost before, but a
dropped declaration now *warns*. See
[[file:plans/same-format-fidelity.org][plans/same-format-fidelity.org]]
§ STATUS for the precise line between done and not.

** WHAT THIS WORK IS
It began as a request to make =geosetta= read a file, let *another program*
modify the feature collection, and write it back. That turned out to be
possible already, and the interesting question was why it is not *faithful*.
Chasing that produced a standing rule:

#+begin_quote
*Reading a format and writing the same format loses nothing.* A capability gap
in the target is a defence for dropping data; the target being the source's own
format is not.
#+end_quote

Everything else is consequence.

** THE NINE DECISIONS
Each is recorded in full, with rejected alternatives, in the plan that owns it.
One line each so you know what has already been settled:

| # | decision | where |
|---+----------+-------|
| 1 | Natives channel lands *before* the format-check deletion | =same-format-fidelity.org= § SEQUENCING |
| 2a | The invariant binds *the whole container*, not just the layer | § THE DOMAIN OF THE RULE |
| 2b | It covers *any file the crate reads without rejecting* | § THE DOMAIN OF THE RULE |
| 3 | CRS dialect is information; the GeoParquet hop owes a warning | =lossy-conversion-warnings.org= § OWED WARNING |
| 4 | Derived splits by risk: information *recomputed*, capability *rebuilt if present* | =same-format-fidelity.org= D4 |
| 5 | New-spoke obligation enforced by a catch-all-free fixture =match= | D6 |
| 6 | Warning-scope question consolidated and *blocked on M1* | =lossy-conversion-warnings.org= § OPEN QUESTION |
| 7 | In-place: fix identity loss first, atomic writes second; gpkg append stays | =edit-composability.org= D4 |
| 8/9 | =--print-crs= one-pass and multi-layer piping both *closed* | =edit-composability.org= § OPEN QUESTIONS |

*Three later rulings extended D1*, all worth knowing before you design
anything. The third is scoped but *not yet built* -- =FieldDecl= gains the
column's *declared type* (M4), which is what lets an all-null FlatGeobuf
column keep it, a GeoPackage =BOOLEAN= survive its reader, and a =DateTime=
stop returning as =String= (defect 5). *Its vocabulary is an open question*,
deliberately: the IR's own four column types are measurably too narrow, so M4
opens by deciding how far the IR follows each format's. The first two:
collection =name= and the *column schema* (=width=/=precision=/=scale=/
=nullable=/=unique=/=primary_key=) are **modelled in the IR**, not carried as
opaque natives. The reason is D5 -- a native does not cross a pipe, so only a
modelled field lets an external tool widen a declaration mid-flight alongside
the value that outgrew it. *Both are implemented*; the schema half lives in
=crate::FieldDecl= and =FeatureCollection::schema=.

** LIVE BUGS FOUND, NOT FIXED
Ordered by how likely they are to bite a real user.

*The list positions below are reading order, not defect numbers.* The canonical
numbering is =same-format-fidelity.org= § Five defects, and each entry names
its own identity in bold; entries with no such name are not one of the five at
all. This is worth stating because an earlier draft numbered these entries
1--5 and then referred to them as though they *were* the plan's numbers, which
made § THE SEQUENCING above -- where "defects 1--2" correctly means the
FlatGeobuf null cell and the GeoPackage boolean -- read as a contradiction of
this section. It never was one; the two lists were simply counting different
things. /Reconciled 2026-08-20./

1. *A GeoPackage edit loop silently duplicates layers.* Not one of the four --
   it belongs to =edit-composability.org= D4, which calls it *live bug 1*.
   *HALF FIXED 2026-08-20; still reproduces.*
   =geosetta a.gpkg - --to fgb | tool | geosetta - a.gpkg --from fgb= leaves
   the pre-edit features *beside* the edited ones, so a middle stage that
   deleted features leaves the deletions undone. Two causes, and only one is
   gone: the FGB writer no longer hardcodes =geosetta= into the header name and
   =main.rs= now consults =fc.name= before the file stem, *but the GeoPackage
   reader still does not set =fc.name= from the table name*, so the FGB on the
   wire has no name to carry. /Re-measured after the FlatGeobuf spoke: still
   appends a =layer= table./ Closes with the GeoPackage spoke. *The workaround
   works today: pass =--layer <name>=.*
2. ~~*Shapefile narrows the schema.*~~ Also not one of the four -- it is the
   inventory's own finding, M1 § 3. *FIXED 2026-08-20* by D1's column
   schema. An 80-character =.dbf= field used to return sized to today's longest
   value; it now returns 80. Verified through a FlatGeobuf transit, which is
   the only route that carries it -- =shp -> geojson -> shp= and
   =shp -> gpkg -> shp= still narrow, and now warn.
3. *A =gpkg= → =gpkg= run destroys the container* around the layers: user
   tables, =gpkg_metadata=, =gpkg_extensions=, every R*Tree. Exit 0, no
   warning. This is *defect 3*.
4. *FlatGeobuf drops null cells* -- *defect 1*. The column survives in the
   header and the reader will not restore an omitted cell to null.
   /Re-measured and re-scoped 2026-08-20; still reproduces, and it is *two*
   losses, not one./ Fixing the cell is necessary and *not sufficient*: an
   all-null column then returns as =String=, because =infer_columns= has no
   values to infer from and =FieldDecl= carries no *type*. /Measured/ on a
   real =ogr2ogr= FGB with an all-null =Integer= column -- GDAL round-trips it
   as =Integer=, geosetta loses the column outright.

   *The unset-vs-null worry recorded here on 2026-08-20 was wrong and has been
   retracted.* It read =ogrinfo='s display convention as GDAL's data model.
   =ogr2ogr= itself writes an explicit =null= for every declared column in
   every feature on GeoJSON output, and -- decisively -- *GeoParquet,
   GeoPackage and CSV already do exactly that in this crate today*, with
   Shapefile rectangular too. FlatGeobuf is the lone outlier, being the only
   format rectangular in its header and sparse in its rows. There is no fork
   to settle. See =same-format-fidelity.org= § Five defects for the
   spoke-by-spoke measurement.
5. *GeoPackage loses booleans* -- *defect 2*. The writer declares =BOOLEAN=
   correctly and the reader never reads the declaration. *This is defect 1's
   second half in another format*: both are a declared column type on disk
   that the IR cannot hold, and both close with a declared type on
   =FieldDecl=. Plan M4 now scopes them as one piece of work.
6. *Every spoke narrows a declared column type to the IR's four* --
   *defect 5*, /found 2026-08-20 while reviewing defect 1/. Placed last here
   and *first* in importance: unlike defect 1 it needs no null to show
   itself, so it fires on most real =ogr2ogr= output. /Measured/, all rows
   populated: FlatGeobuf =Integer(Int16)= returns =Integer64=,
   =Real(Float32)= returns float64, and *=DateTime= returns =String=* -- a
   temporal column silently becoming text. =ogr2ogr= preserves all three.
   =schema::ColumnType= has four values; FlatGeobuf's =Column.type= names
   fourteen. This is what re-scoped M4 and why its step 0 is an
   investigation: the declared type has to carry the *source's* vocabulary,
   not the hub's.

*Defects 1, 2 and 5* -- entries (4), (5) and (6) above -- are the
free-standing group in the sequencing diagram, plan M4, shippable at any time.
They are also *one piece of work*, not three that happen to be small: see M4's
scoping, which settles the type vocabulary first because none of them closes
without it.
*Defect 3* is entry (3) and travels with the GeoPackage container (M3b).
*Defect 4* is not in this list because it is done: it was the FlatGeobuf
header's hardcoded =geosetta= name, retired with the FlatGeobuf spoke.

** REPRODUCING THE MEASUREMENTS
Every claim marked /measured/ was run against the release binary
(=target/release/geosetta=, workspace target dir -- note =geosetta/target/= is
a stale leftover and its binary predates =--crs=) and GDAL 3.13.2. The fixtures
are in the tree, so most re-run directly, e.g.:

#+begin_src text
geosetta tests/fixtures/gdal_hostile.gpkg - --to geojson --layer cities
geosetta tests/fixtures/hand_hostile.csv - --to fgb | geosetta - - --from fgb --to csv
#+end_src

Two traps that already cost time once each:
- *Do not write fixtures through a shell heredoc.* It silently mangled
  =København= to =Ke\xe2\x88\x9a\xe2\x88\x8f...=. Write with explicit encoding
  and check the raw bytes.
- *=strings= defaults to a 4-character minimum*, which hid a 3-character
  column name and produced a wrong conclusion about FlatGeobuf's header. Use
  =strings -n 1= when decoding fixtures by hand.
- *=tests/fixtures/gdal_hostile.fgb= does not exercise column widths*, despite
  being the fixture the inventory cites for FlatGeobuf's =Column= table. It was
  written *from the GeoPackage*, which has no widths, so every column reads
  =String (0.0)=. To exercise them, write a fresh FGB from
  =gdal_hostile.shp=. The =0.0= is itself a useful case -- it is what proved
  that GDAL writes =width: 0= for "undeclared".

** THE ONE REAL GAP -- *RETRACTED 2026-08-20, it was a measurement error*
This section claimed *"this repository has no commits at all"* and recommended
an initial commit. Both were wrong, and the way they were wrong is worth
keeping.

=geosetta= has full history -- =git log= shows =2a12bab=, =a1c9bc1=,
=028314a= and back through the 0.2x releases. What actually happened is that
=git= was run from =geocore/=, which is *not* a repository: the search walked
up to =~/Projects=, which *is* one, has no commits, and holds every unrelated
project the user owns. So the "no commits" reading was true of a repo nobody
meant to look at.

*The trap, for whoever runs =git= here next:* =geocore/= is a bare workspace
directory containing two independent repos, =geosetta/= and =geoscribe/=,
inside an outer =~/Projects= repo that should almost certainly never be
committed to. *Always run =git= from =geosetta/= itself*, and check
=git rev-parse --show-toplevel= before staging anything -- a =git add -A= one
level up would sweep in =basin/=, =hen/=, =sphere2/= and a =.venv=.

The fidelity work described in this handoff /was/ uncommitted while it was
being done, which is what made the error plausible. It is committed now, so
§ WHAT CHANGED IN EXISTING DOCS is no longer the only substitute for a diff --
prefer =git log= / =git show= over that section where the two disagree.

** OPEN QUESTIONS WORTH KNOWING
Not blockers, but they will come up:
- *Is canonicalisation a loss?* =MULTIPOINT ((1 2))= → =MULTIPOINT (1 2)=,
  =linestring= → =LINESTRING=. Decides whether the CSV/WKT lexeme problem is
  two bugs or a whole class. (=native-inventory.org= § QUESTIONS, item 1.)
- *=edges= / =epoch= in GeoParquet* -- no available tool emits either, so no
  fixture exists. *Do not close this as a null result* the way =envelope.org=
  closed the GPKG XYM indicators: =edges: "spherical"= would restate what the
  coordinates *mean*, which is a semantic corruption, not a dropped member.
- *Raster GeoPackages* -- container scope puts tile pyramids in the domain
  while geosetta is vector-only. Recommendation on file is to *reject* a
  populated tile container rather than silently drop the imagery.
