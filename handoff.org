** WHAT THIS SESSION CHANGED
Three questions answered, two defects found and fixed, one plan written.

*** 1. Q1 -- canonicalisation -- ANSWERED, and the CSV half shipped
=native-inventory.org= § QUESTIONS item 1, filed 2026-08-20 and **the oldest
open question in this body of work**.

***Decision 31 / =same-format-fidelity.org= D17: a reader may replace text with
a parsed value only when its own writer renders that value back to the exact
text read.*** Where it cannot, the text stands.

The question had been holding *three different problems as one*, which is why
it sat: a *spelling* change (=1.50= → =1.5=), a lost *value identity* (=007= →
=7=, where the text was the data) and *a different number* (past =i64=, through
an =f64=). Only the first was ever the canonicalisation argument.

**What draws the line is who decides the type, not which format it is.** A CSV
cell and a KML =ExtendedData= value are untyped text, so typing them is the
reader's decision and D17 binds it. A JSON number and a WKT coordinate are
numbers *by grammar*, so those spokes declare the loss instead.

*Built*: =csv.rs='s =refuses_typing= gate, rendering through =cell_text= so the
reference is this spoke's own writer -- which makes its reader and writer a
*fixed point* on cell text. **The verdict is per column**: one refused cell
types the whole column as text, because =[007, 08001, 12345]= read per cell
returns two strings and a *number*. Only a *refusal* gates a column; a plain
=hello= beside a =7= has no typed reading to refuse and leaves its column
alone.

*Measured on =hand_hostile.csv=*: =007=, =08001=, =12345678901234567890=,
=1.50=, =22.250=, =TRUE=, =" spaced "=, =København= and ="Zürich, CH"= all
survive byte-identical, plus =+7=, =1e2= and =1.0= -- three spellings nobody
had enumerated, which is the argument for a rule over the named-exception list
this nearly became.

*Also corrected*: =Format::GeoJson='s loss list. A =geojson -> geojson= run
reformats numbers exactly as =csv -> csv= did, and the table had named only
=bbox= and geometry foreign members -- one loss, two stories, in a warning a
user reads.

*Ruled and deliberately not fixed*: GeoParquet's parsed =JSON=-annotated column
(={"a": 1}= re-serializes without the space). Gating =push_json_embedded= the
way =infer_value= is gated looks like the same change and is not -- the parse
is also what gives =DeclType::Json= its meaning, and =Format::recast='s pinned
table is written against the parsed reading. It stays with the GeoParquet spoke.

*** 2. D6's fixture registry -- BUILT, and it found defect 24 immediately
Decided 2026-08-20, unbuilt until now. =tests/same_format.rs= holds
=hostile_fixture(Format) -> Fixture= -- one arm per spoke, no catch-all -- plus
=round_trip=, which is *also* catch-all-free because its three arms are the
three on-disk shapes this crate has (one buffer, a container of layers, a set
of sibling files) and a fourth cannot be assumed.
=every_format_puts_back_what_its_reader_recovered= drives both.

=Format::ALL= landed with it, its completeness compiler-enforced the same way
rather than by counting. Both array literals D6 named are converted:
=display_name_uses_each_format_s_own_spelling= and the loss-table test's
neighbour.

***An earlier draft compared two generations of output bytes and passed all
nine formats immediately -- which was the tell.*** A writer that drops a member
uniformly, or settles on a permutation, is **idempotent**: generation 2 agrees
with generation 1 about the loss.

#+begin_quote
*Byte equality across a hop measures the writer against itself. IR equality
measures it against the reader.*
#+end_quote

**Worth knowing before anyone "strengthens" this test into a byte comparison.**
What it cannot see is a member dropped at *read* -- a KML =<Style>= never
reaches the IR, so both sides agree about a file that already lost it. That
half stays =Format::same_format_losses='s and the inventory's, which is why the
registry records what each fixture carries.

*** 3. Q3 -- Shapefile sidecars -- ANSWERED, and it was not about indexes
=native-inventory.org= § QUESTIONS item 3 asked whether derived-capability
index sidecars should be rebuilt. ***Decision 33: a Shapefile write writes the
sidecars it can, deletes none, and warns about the rest.*** Policy lives at
=plans/shapefile.org= § THE SIDECAR POLICY, which the warnings themselves cite.

- ***=.cpg= is written, always, saying =UTF-8=*** -- the one member of the set
  whose right answer this writer always knows, and under no-deletion the only
  thing that stops a foreign one from relabelling our text. /Also closes
  =native-inventory.org='s one-sided =.cpg= gap./
- ***A surviving sidecar is warned about by name***, saying what it will be
  read as. Twelve extensions covered.
- ***=.qix=/=.sbn= are still not written.*** D4's "rebuilt when the source
  carried one" is triggered **nowhere today**, GeoPackage included --
  =main.rs= passes only =args.rtree= -- so extending an unimplemented rule to a
  second spoke before the first would be backwards. It belongs on
  =spatial-index.org= as one piece of work across both spokes.

*Deletion was rejected on principle.* =ogr2ogr -overwrite= removes the entire
prior file set /(measured)/; a conversion must not remove files nobody asked it
to touch.

*** 4. plans/encodings.org -- written, scoping only
Crate-wide and deliberately not a Shapefile plan. Per-spoke, **half the spokes
refuse non-UTF-8 input outright and half guess** -- opposite failure modes
needing opposite fixes, and nobody chose the split. A Shapefile carrying
Latin-1 text reads fine; *the same bytes* in a CSV are refused.

Correctness before capability: E1 warns when an unrecognised =.cpg= is
approximated as Latin-1 (silent today), E3 refuses a multi-byte codepage rather
than producing mojibake, then E2's single-byte tables and E4's =--encoding=.

*** 24 -- a =fgb -> fgb= run silently permuted the user's features
**Found by D6's fixture registry on its first run; FIXED 2026-10-21.** Live
since the packed R-tree shipped (=spatial-index.org= milestone B).

=flatgeobuf/writer.rs= called =hilbert_order= on every write where each feature
had a geometry, so =gdal_hostile.fgb='s two features came back *swapped*. Both
the source and our output carry =index_node_size = 16=, so this was not a
producer that had skipped the index -- GDAL simply does not order its leaves
the way we did.

***The sort was never a requirement of the structure.*** A packed R-tree is
packed bottom-up over whatever order its leaves are in, and a reader walks it by
bbox either way; the Hilbert part of the name describes the *locality* a sorted
build buys, not a correctness condition. So the sort was spending content for a
performance property, on every run, with no way to decline.

***And there was already a flag for it, which this made meaningless.***
=main.rs= applies =--sort-hilbert= to the IR *before* calling the writer, so for
FlatGeobuf the sort was **mandatory where the CLI advertised it as opt-in** --
and opt-in for GeoPackage's =--rtree= in the same breath, on the stated
reasoning that an index is "a size/query optimization, not a correctness
requirement". /The flag's doc comment read "a no-op ordering-wise for
already-sorted FlatGeobuf", which has the causality backwards: it was a no-op
because the writer sorted regardless./

The fix is a *deletion* -- the writer packs the index over input order -- so
order is preserved by default, no capability is lost, and the flag means one
thing everywhere.

**Three things worth keeping.**

*It was invisible to every test in the tree, and to the obvious test.* The sort
is **idempotent**: generation 2 of our own output agrees with generation 1 about
the permutation. It also needed a *foreign producer's* order to show at all,
which is precisely what a hostile fixture is for.

*Self-consistency could not have validated the fix either*, so the oracle is
GDAL against a **brute-force** expectation:
=gdal_filters_correctly_through_an_index_over_unsorted_leaves= builds 500
features sorted against locality, past =NODE_SIZE= twice over so interior node
boxes genuinely overlap, and requires =ogrinfo -spat= to match a count computed
in the test. /Our reader walking our own tree would have agreed about a broken
one./

*A test for one half of a correlated pair is satisfied by breaking the other.*
=features_keep_their_input_order_and_the_file_is_still_indexed= asserts both
together on purpose: order alone is satisfied by dropping the index, the index
alone by sorting again.

*** 25 -- a Shapefile write adopted whatever sidecars were already there
**Found while answering Q3; PARTLY FIXED 2026-10-21.** Live since the Shapefile
spoke shipped.

=write_shapefile_to_path= writes =.shp=/=.shx=/=.dbf= and a =.prj= *when the
collection has a CRS*. Everything else at that basename survived the write and
then described the output beside it. Measured:

| left behind | effect |
|-------------+--------|
| =.prj= | a CRS-less CSV's degrees came back =NAD83 / UTM zone 18N= in *metres* -- from =ogrinfo= and from =geosetta --print-crs= alike |
| =.cpg= | one reading =ISO-8859-1= turned =København= into =KÃ¸benhavn= for GDAL **and for geosetta's own reader** |
| =.qix=/=.sbn= | an index describing different geometry; could not be made to give GDAL a wrong answer in any configuration tried |

***The =.cpg= case is the one that should sting***: geosetta wrote correct bytes
and then read them back wrong. A round trip through one tool, corrupted by a
file neither end of it wrote.

*Fixed by writing =.cpg= (always =UTF-8=) and warning about the rest*, per
decision 33.

**Four things worth keeping.**

*A question's own framing can hide the defect.* Q3 asked about *rebuilding
derived capabilities* -- a performance concern -- and the same gap was leaking
*information*: a CRS and a text encoding. The index, the thing actually asked
about, turned out to be the harmless member of the set. /Answering the question
as asked would have ruled "no" and moved on./

*"The reference does the same thing" bounds how unusual a gap is, never how
much it costs.* =native-inventory.org='s own priority note had deferred =.cpg=
on exactly that argument. Both halves failed on re-measurement: the cost had
nothing to do with symmetry, and ***=ogr2ogr='s default declares LDID =0x57= --
ANSI/Windows-1252 -- while writing UTF-8 bytes***, so the reference is not
silent about encoding, it is wrong about it through a different channel.

*Whether two filenames are two files is a property of the filesystem.* The
first version of the check probed =Path::exists= for the upper-cased spelling
*before* writing and reported every sidecar twice on this machine. It now runs
*after* the write and compares bytes, which is the only test honest on both
case-sensitive and case-insensitive filesystems.

*A warning that fires on the write cannot cover the read.* A later
=geosetta out.shp …= reads a stale =.prj= as simply the file's CRS and says
nothing -- by then no evidence remains. That asymmetry is the argument for
writing whatever can be written rather than warning about it, and it is why
=.cpg= is written rather than reported.

** WHAT WAS LEARNED
1. ***A question's framing can hide its own answer.*** Three for three this
   session -- Q1 was three questions, D6's answer was a defect, Q3 was not
   about indexes. Measure before answering a question that has been sitting.
2. ***Byte equality across a hop measures a writer against itself.*** A uniform
   drop or a settled permutation is idempotent and invisible to it.
3. ***A rule catches what a list does not.*** D17's gate caught =+7=, =1e2= and
   =1.0=; the named-exception alternative would have missed all three.
4. ***"The reference does the same thing" bounds how unusual a gap is, never
   how much it costs.***
5. ***A test for one half of a correlated pair is satisfied by breaking the
   other.***
6. ***Whether two filenames are two files is a filesystem property*** -- a
   check comparing spellings must write first and compare bytes.
7. ***A decision stated in a plan and triggered nowhere is not a decision the
   code honours.*** D4's "rebuild if present" reads as settled and fires for no
   spoke.
