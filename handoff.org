** THE STANDING RULE THIS SESSION ADDED
Editing what was read, through the API, is a goal of the crate, for *every*
attribute -- geometry, properties, native, and the collection's own fields --
and no layout change may make an edit worse than the row IR made it. Every
attribute has an owned hatch: an edit as ordinary Rust on the row IR's own
types. This is D-C16; =tests/edits.rs= pins it and must pass unchanged
through every later step.

** TRAPS
- Timing with =memprobe= while =equiv.py= runs is meaningless; equiv runs
  six conversions at a time.
- The pinned binaries =equiv.py= caches live under
  =$TMPDIR/geosetta-equiv/pin-<commit>/target/release/geosetta=; the C5 pin is
  =pin-c4c43511d590=, handy for whole-process timing against C5. Those pins
  are built from =git archive= without =bench/=, so memprobe against an old
  revision needs its own archive: =git archive <rev> | tar -x -C <dir>=,
  then =cargo build --release --manifest-path bench/memprobe/Cargo.toml=
  there.
- =tests/budgets.rs= prints what each case measures only with
  =GEOSETTA_BUDGET_REPORT=1= /and/ =-- --nocapture=; the numbers are the
  same in debug and release.
- =tests/nazca_sink.rs= runs against nazca from crates.io, even inside the
  workspace, not the =../nazca= beside it: a change there reaches the test
  only after a release, or through a =[patch.crates-io]= in the workspace root.
- =equiv.py= cannot build a pin at c8f7ba5: that commit's manifest names
  =../nazca= by path, which a =git archive= does not hold. Pin 2491146 or
  anything after the manifest moved to crates.io instead.
- =compare.py= takes =BIN== for another binary; run it with =VERIFY=0= for a
  pin to save the =ogr2ogr= read-back, and never two runs at once.
