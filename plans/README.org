#+AUTHOR: Daniel Okuniewicz Jr.

* Plans
Design notes, one self-contained plan per file, ordered by dependency. Most are
implemented — each entry says so; the few marked /scoping only/ are not.

** Sourcing a fixture from a real tool
Written down because it keeps recurring — Shapefile, GeoParquet, GeoPackage and
Z/M work each rediscovered it from zero. Every wire-format detail in this crate
is confirmed against real tool output before it is implemented, never inferred
from the spec alone, and this is the shape that confirmation takes:

1. *Try the obvious case.* Ask the tool (=ogr2ogr=, =projinfo=, DuckDB) to
   produce the thing you want a fixture for.
2. *When you get nothing, find out why before retrying.* A null result is
   information, not a dead end. GDAL writes no GeoPackage envelope for a
   degenerate =POINT= bbox but does for a =LINESTRING=; a fixture built on the
   point would have "passed" while exercising nothing.
3. *Retry with a shape that avoids the degeneracy*, and record in the fixture's
   test comment *why that shape* — otherwise the next person simplifies it back
   to a point.
4. *Hand-decode the actual bytes and cross-check them* against what the geometry
   should be, before trusting the file. Every layout claim in this crate traces
   to a decode someone did, not to a spec paragraph.

*A null result can be the finding.* If no tool will produce the artifact at all,
that is worth more than a fixture: it usually means nothing consumes it either,
and shipping a from-spec guess would be unverifiable. =envelope.org= is the
worked example — GeoPackage's spec defines XYM and XYZM envelope indicators,
but GDAL emits neither across eight geometry families, under any creation
option or config switch. The right response was to stop at Z and write down
why, not to implement the spec's table from symmetry.

** Plan index

- [[file:reverse-roundtrip.org][reverse-roundtrip.org]] :: GeoParquet → GeoJSON,
  reading back Geosetta's *own* output. The reader skeleton (thrift reader,
  footer parsing, single-page PLAIN/RLE decode, WKB decode, GeoJSON serialize).
  *DONE* — implemented in =parquet/reader.rs=; the geojson→parquet→geojson→parquet
  round trip is byte-for-byte stable.
- [[file:arbitrary-geoparquet.org][arbitrary-geoparquet.org]] :: Extend that
  reader to files from DuckDB / GDAL / Arrow — dictionary encoding, the general
  RLE/bit-pack hybrid, multiple pages/row groups, more codecs and types, and a
  schema-tree walk so columns nested under OPTIONAL groups (e.g. GDAL's
  =geometry_bbox= covering column) decode correctly instead of misparsing.
  *Depends on the round-trip reader.* Largely done (see the file for the
  remaining deferred items).
- [[file:flatgeobuf.org][flatgeobuf.org]] :: Add FlatGeobuf as a new format
  spoke — a from-scratch FlatBuffers codec, an FGB reader/writer against the
  shared =Feature= IR, and hub routing so FGB composes with GeoJSON and
  GeoParquet automatically. *DONE* (both directions).
- [[file:geopackage.org][geopackage.org]] :: Add GeoPackage — a from-scratch
  SQLite reader/writer, treating the multi-layer =.gpkg= as a layer-aware
  wrapper around the single-layer IR (read fans out over all layers; write
  creates-or-appends one layer, rewriting the whole file). *DONE* (both
  directions).
- [[file:spatial-index.org][spatial-index.org]] :: Spatial ordering and indexing
  — shared per-feature bbox + Hilbert curve primitives, the FlatGeobuf packed
  Hilbert R-tree on write, optional GeoParquet Hilbert clustering, and the
  GeoPackage R*Tree extension (=--rtree=). *Milestones A–D DONE; E open* —
  GeoParquet 1.1's =covering= bbox column, which this crate reads and cannot
  write, handed over from =same-format-fidelity.org='s GeoParquet spoke
  (2026-08-20) because it is a D4 rebuild-if-present index like the other two,
  not a native.
- [[file:streaming-progress.org][streaming-progress.org]] :: Intra-stage progress
  — thread an optional, throttled progress callback through each reader/writer so
  =--progress= can show a live percentage on large files (the current flag only
  reports per-stage). *Enhancement, not yet implemented.*
- [[file:performance.org][performance.org]] :: Read/write throughput — the
  =tests/perf.rs= harness (=throughput= + =wide_table= benchmarks) and
  =bench/compare.py= (vs ogr2ogr/duckdb). *DONE*: the GeoJSON writer's
  JsonValue-tree bypass (~2× on =* → geojson=) and the symmetric streaming
  reader (~1.35× on GeoJSON read); =schema::infer_columns= fixed from
  O(rows×cols²) to O(rows×cols) via a =HashMap=-keyed pass, then further to a
  lazy-backfill single pass that skips the per-row sweep over every known
  column entirely (measured via =sample= time-share, since whole-process
  wall-clock was too noisy at these scales) — the win widens with column
  count, and now shows up in =compare.py='s dedicated wide-column case as an
  8–10× margin over ogr2ogr/duckdb, vs 5–9× on the narrow, 4-property cases;
  Parquet read de-duplication (dropped the second per-cell copy) and
  reader-internal column fusion; bulk-copy string writing instead of
  char-by-char; =Rc<str>= property-key sharing/interning to cut per-row key
  allocation; a Parquet all-present level-decoding fast path and WKB =Vec=
  pre-sizing to avoid reallocs. *Memory* (2026-10-28, measured by peak RSS in
  =compare.py= and a phase-splitting allocator probe): =Feature::native= boxed
  and GeoJSON properties sized exactly (Mem1--2), property columns borrowing
  the features' cells (Mem3, which also removed a quadratic FlatGeobuf write),
  Parquet decoded a column at a time (Mem4), and KML written straight into its
  text with no element tree (Mem5: 600 → 85 MB on 100 000 points). *Write
  speed* (2026-10-29): a whole float formatted without Rust's exact-precision
  path (item 8, −32% on a wide GeoJSON write), KML's =<Data>= written in one
  step (item 9, with 8 −55% on a wide KML write), and KML's typed columns
  made linear in the column count (item 11, minutes to seconds on 2 000
  columns). What is left is KML's read, and KML carried back to KML.
  *Remaining:* a hand-rolled float formatter
  (dtoa/Ryū) is parked — correctness-risk and effort not worth it yet against
  =std='s formatter; the compression codecs are untuned but unlikely to be the
  bottleneck; full streaming (vs. whole-file-in-RAM) is tracked separately in
  [[file:streaming-progress.org][streaming-progress.org]].
- [[file:columnar.org][columnar.org]] :: The hub as a table rather than rows:
  typed column buffers with validity and presence bitmaps, a row's own key
  order recorded only where it deviates, and a =Number= column that keeps =1=
  and =1.0= apart, so every same-format guarantee holds. Every format fits;
  GeoJSON and KML need the exceptions. Milestones C0--C6, from an in-repo
  equivalence harness to geometry buffers. /C0 built (=bench/equiv.py=,
  =bench/memprobe/=); the IR itself not started./
- [[file:crs.org][crs.org]] :: CRS pass-through across all formats — warnings when
  a CRS-degrading target (GeoJSON/CSV/WKT) can't express the source CRS (those
  formats stay as-is), making authority+code universal among the rich formats,
  and structural WKT→PROJJSON translation for GeoParquet. Milestones A (CRS-loss

  — no safe disambiguation) and bare-code definition synthesis, which geosetta

  via =--crs= — see
  [[file:crs-external-resolution.org][crs-external-resolution.org]]. The
  PROJJSON→WKT reverse is *DONE* — see
  [[file:projjson-to-wkt.org][projjson-to-wkt.org]].
- *CRS registry* (REMOVED from this repo in 0.24.0) :: An embedded
  =(auth,code)→{PROJJSON,WKT1,WKT2}= blob covering all 13 790 CRSes in
  =proj.db=, in ~1 MB, reached through the opt-in =crs-registry= feature and the
  sibling =geoscribe= crate; =geosetta='s =crs/registry.rs= was a thin
  call-through plus the identity-*recovery* policy (name→code, ellipsoid-
  validated) layered on it. *Removed* along with the feature and the dependency:
  it was this crate's only dependency of any kind, and
  [[file:crs-external-resolution.org][crs-external-resolution.org]]'s =--crs=
  closes the same bare-code gap at run time, for pre-built binaries too. *The
  default build is unchanged* — every registry entry point was a =None= stub
  off-feature, so removing them is a no-op there; only a =--features
  crs-registry= build loses anything. What it loses is name→code recovery from
  an id-less WKT, and only narrowly (geographic CRSes, id-less sources,
  GeoParquet output — the projected resolver was never wired in at all). Its
  mechanism *was* the lookup table, so it has no data source here; restoring it
  properly is scoped in the sibling repo as =geoscribe/plans/wkt-identify.org=.
  The registry itself lives on in =geoscribe=, usable as an ordinary library or
  CLI by anyone who wants it; geosetta simply no longer depends on it.
- [[file:shapefile.org][shapefile.org]] :: Add Shapefile — the first *multi-file*

  shape of GeoPackage's one-file-many-layers), a from-scratch mixed-endian

  Esri-flavor WKT1 is the original driver for
  the whole registry pivot; R2's geographic name-recovery already applies to it

  =registry::def_wkt=. *Depends on the CRS registry* (for full =.prj= fidelity;
  geometry/attributes have no dependency on it).
- [[file:kml.org][kml.org]] :: Add KML/KMZ — a from-scratch XML reader/writer
  (=src/xml.rs=) and a minimal ZIP container codec (=src/zip.rs=, stored +
  the existing DEFLATE decoder for reads, stored-only for writes), with CRS
  =Crs::Wgs84= -- or EPSG:9707 since =kml-standard.org= D-K12, when every
  height is =absolute=. *DONE* (=.kml= and
  =.kmz=, read + write, both directions, wired into the hub via
  =Format::Kml=/=Format::Kmz=) — oracle-validated against real GDAL

  =<NetworkLink>=). No dependency on the other plans.
- [[file:kml-standard.org][kml-standard.org]] :: Rescope the KML spoke to the
  standard — OGC KML 2.3 as a typed document model in the KML native, with the
  IR as its projection; both OGC versions (2.2, 2.3) read and detected; output
  in the version asked for (=--kml-version=), defaulting to the source's own.
  It is =same-format-fidelity.org='s M3 KML spoke (D18) and supersedes parts of
  =kml.org=. Depends on =lossy-conversion-warnings.org= § 2b and
  =encodings.org=. *DONE 2026-10-28*: K1--K5 built, every question decided
  (D-K1 to D-K16), and every kind of write validated against its version's
  schema by =tests/kml_schemas.rs=. D-K17 (2026-10-29): a null is left out of
  =<ExtendedData>=, as GDAL writes it, and warned.
- [[file:kml-layout.org][kml-layout.org]] :: How a KML document is laid
  out on write, balancing the source's layout against well-formatted output:
  the source's whitespace and DOCTYPE are kept where geosetta did not touch
  them; what geosetta writes follows the document's inferred style, or a
  two-space house style for a new document; lexical form (quotes, references,
  CDATA, which is always written escaped) is normalised and is not a loss.
  =--compact= (D-L8) writes GeoJSON and KML on one line; both are indented
  by default. Answers =todo.org='s "KML's XML-layer losses" but the
  encoding, which is =encodings.org= E6. *Built 2026-10-28*: L1--L4.
- [[file:projjson-to-wkt.org][projjson-to-wkt.org]] :: The reverse of
  =crs.org= milestone C — translate a PROJJSON CRS with no authority code
  into WKT1, so a GeoParquet source can still express its CRS when converted
  to FlatGeobuf/GeoPackage/Shapefile. *DONE* (geographic and projected, both
  directions verified against real =projinfo=/=ogrinfo=) — closes
  [[file:crs.org][crs.org]]'s "PROJJSON→WKT reverse" item. Shares
  =crs.org='s WKT→PROJJSON translator's file, its =UnitKind= types, and —
  for projected CRSes — its =wkt1_tables.rs= crosswalk, reversed rather than
  rebuilt.
- [[file:compression-encoders.org][compression-encoders.org]] :: Close the
  read/write asymmetry in =compress/= — GZIP/DEFLATE, LZ4, and ZSTD are
  decode-only today (built for =arbitrary-geoparquet.org='s foreign-file
  reading; only Snappy has ever needed an encoder, for the GeoParquet
  writer). DEFLATE is prioritized first: it has a real, immediate consumer
  in =kml.org='s stored-only =.kmz= writer, and a fixed-Huffman-only design
  (reusing =gzip.rs='s existing fixed tables) keeps the lift small. LZ4 and
  ZSTD have no current consumer and are deferred accordingly — ZSTD
  especially, since a real compressing encoder is comparable in effort to
  its 1000+-line decoder. *Scoping only, not yet implemented.*
- [[file:reproject-composability.org][reproject-composability.org]] :: Make
  Geosetta composable with any *external* reprojection tool without ever
  reprojecting itself — a coordinate-mutation seam
  (=for_each_position_mut=/=for_each_position_run_mut=) for a linked-in Rust
  library, and =-= stdin/stdout piping (=main.rs=/=cli.rs=) for a separate
  process. *DONE* — verified against three independent, real tools (GDAL,
  PROJ, and the =wbprojection= crate) in =tests/reproject_pipe.rs=. *Depends
  on =crs.org='s opaque-CRS design* (the IR never interprets a =Crs=, so
  swapping it out after an external transform needs no Geosetta-side code).
- [[file:crs-external-resolution.org][crs-external-resolution.org]] :: Close the
  gap where a source carries an authority+code but no expanded WKT/PROJJSON
  body, so targets needing a full definition (GeoParquet, Shapefile's =.prj=)
  warn instead of resolving — not by geosetta shelling out itself (an earlier
  framing, rejected on security grounds: silently executing an arbitrary
  same-named binary off =PATH= with no visible action), but by a =--crs
  <path|->= flag accepting externally-resolved WKT/PROJJSON text, plus a
  =--print-crs-code= diagnostic so the unresolved code can be extracted and
  piped to *any* tool that speaks those forms — every subprocess visible in the
  user's own command line, none hidden inside geosetta. *DONE* (0.24.0), and
  since =crs-registry='s removal in the same change it is the crate's only
  answer for a bare code. Verified end to end in =tests/crs_external.rs=,
  including one case piping through a real =projinfo=.
- [[file:zm-geometry.org][zm-geometry.org]] :: Carry a Z (elevation) and/or M
  (linear-referencing measure) ordinate through the IR and every format spoke,
  instead of silently dropping them (GeoJSON, KML) or rejecting the input
  outright (Shapefile =PointZ=/etc.) as three spokes originally did. Widens
  =Position= from =[f64; 2]= to a struct carrying optional =z=/=m= fields —
  every =Geometry= variant's shape stays the same, only the leaf type grows —
  which is source-breaking for external code indexing it positionally
  (confirmed harmless for the =wbprojection= dev-dependency specifically, via
  the =for_each_position_mut=/=for_each_position_run_mut= reprojection seam,
  [[file:reproject-composability.org][reproject-composability.org]]; no
  compatibility shim added — pre-1.0, breaking changes are accepted). *All
  nine milestones are DONE (2026-08-17).* Each dimension-flag/keyword
  ambiguity (WKB's ISO-vs-EWKB, WKT's keyword-vs-bare-tuple) and every M
  section's optionality was confirmed against real DuckDB/GDAL output before
  implementing, not assumed from a spec — including a caught-and-corrected
  mistake at M8, where GeoParquet's =geo= metadata was first assumed to have
  no M vocabulary (based on one tool's writer behavior) before the actual
  spec text was checked. Z is now carried end-to-end by every spoke; M is
  fully supported everywhere it can exist (WKB, WKT/CSV, GeoPackage,
  FlatGeobuf, Shapefile — both within Z-shapes and the four M-only shape
  types — and GeoParquet's =" M"=/=" ZM"= metadata suffixes), with GeoJSON
  and KML/KMZ the only spokes lacking M, because neither format has any M
  concept in its own spec. Extracted from
  [[file:arbitrary-geoparquet.org][arbitrary-geoparquet.org]]'s milestone
  6a. Prompted the standing
  [[file:lossy-conversion-warnings.org][lossy-conversion-warnings.org]]
  convention below.
- [[file:lossy-conversion-warnings.org][lossy-conversion-warnings.org]] ::
  Standing convention, not a milestone plan — any format conversion that
  would silently drop/degrade information the source carries must warn on
  =stderr= (suppressible with =--quiet=), never just succeed. Documents the
  two mechanisms this applies to (=Crs::downgrade_warning='s pre-write
  predictive check, Shapefile's =dbf.rs= post-write =Encoded.warnings=).
  *In effect* — closed the GeoJSON/KML M-drop gap and a pre-existing,
  tested-but-unwarned FlatGeobuf/GeoPackage alphanumeric-CRS-code gap in the
  same pass that established the rule. *Generalized* once a second
  near-identical check made the per-check wrapper-function-pair pattern's
  duplication undeniable: =main.rs='s =collect_conversion_warnings=/
  =collect_layer_warnings=/=print_warnings= now do the collecting/de-duping/
  printing for every check in one place — adding a new check is one line,
  not a new function pair plus three call sites.
- [[file:cross-format-audit.org][cross-format-audit.org]] :: What a write
  loses without saying: a round trip through each tabular target, against
  FlatGeobuf as the control, filing every unwarned difference. Found one
  defect -- a KML source written to GeoPackage prints none of the KML spoke's
  warnings (F1) -- and eight losses every tabular target shares (F2--F9),
  each to be carried, warned or left silent on purpose. /Measured
  2026-10-29; nothing built./
- [[file:hostile-input.org][hostile-input.org]] :: Allocations the readers
  sized from counts the file states, before reading the data behind them. Ten
  sites confirmed by reproduction and fixed, among them a FlatGeobuf header
  that silently read as empty, a Snappy prefix that aborted natively, and
  negative Parquet counts that panicked natively. /Fixed 2026-10-29; H1

- [[file:multi-geometry-columns.org][multi-geometry-columns.org]] :: Let a
  source with more than one geometry column per feature — in practice, only
  GeoParquet, and today only DuckDB actually writes it — survive a
  conversion instead of being rejected outright. Adds
  =Feature::extra_geometries= to the IR; extra columns decode for real on
  GeoParquet read, round-trip as real columns on GeoParquet write, and fall
  back to WKT-text properties (with a warning, =crs.rs='s downgrade-warning
  precedent) for every other target format, none of which has a
  format-native concept of more than one geometry per feature. *Scoping
  only, not yet implemented.* Extends
  [[file:arbitrary-geoparquet.org][arbitrary-geoparquet.org]]'s milestone
  6b, whose reject-with-error behavior becomes this plan's read-side
  detection step.
- [[file:crs-definition-output.org][crs-definition-output.org]] :: A
  =--print-crs= flag printing the CRS *definition body* the source recorded,
  verbatim — the missing sibling of =--print-crs-code=, which reports the
  identity and so deliberately reports nothing for an id-less CRS. Without it
  the report-resolve-supply loop has a hole exactly where =geoscribe
  --identify= was built to help: a Shapefile =.prj= is loose WKT on disk and
  needs no help, but every other format buries its CRS in a container that
  =--identify= cannot open. Two flags, not three — a code+body composite would
  be valid input to no tool, violating
  [[file:crs-external-resolution.org][crs-external-resolution.org]]'s
  § TOOL AGNOSTICISM, and carries no information the body alone doesn't. Never
  translates (a dialect option would be a translation request, and the
  crosswalk is what the crate is trying to stop leaning on). *Extends
  crs-external-resolution.org*; adds no dependency and spawns nothing.
  *DONE* (0.25.0, 2026-08-19), together with its other half
  =geoscribe/plans/projjson-identify.org= — neither was useful alone, so they
  landed as one item. The verbatim contract needed a reader change to be true at
  all (=NamedCrs.projjson= had been storing a *re-serialized* definition, not the
  source's bytes); =--escape= ships as the opt-in =cat -v=-alike for reading an
  untrusted file at a terminal; and a GeoPackage's placeholder =NONE= authority
  is no longer reported as an identity, since geosetta invents it.
- [[file:envelope.org][envelope.org]] :: Extend =Bbox= to fold Z and M -- it
  already receives them on every =Position= and discards them -- then emit a
  GeoPackage GPB envelope from the writer, which hardcodes "no envelope" today,
  so an envelope-bearing source =.gpkg= stops losing it on a round trip. Takes
  over =geoscribe/plans/envelope-computation.org=, retired 2026-08-18: this
  crate already owns the fold (=convert.rs:129= writes GeoParquet's =geo= bbox
  from it), and with no dependency edges between the three crates it could not
  have called a sibling's version anyway. Carries that plan's empirically
  confirmed GPB layout forward. Excludes envelopes *under reprojection*, which
  is a different problem and belongs to =geoscribe/plans/transform-bounds.org= (=nazca='s until 2026-10-22).
  *DONE (V1--V4, 0.25.0)* -- =Bbox= folds Z/M, and an opt-in =--envelope= flag writes
  the GPB envelope, matching GDAL's bytes ordinate for ordinate. The design
  question it settled: the envelope *stops at Z*. An envelope is a spatial
  bound and M is a linear-referencing measure, so indicators 3 (XYM) and 4
  (XYZM) have no query to accelerate, and GDAL never emits them under any of
  eight geometry families. That matters because GDAL *trusts* the cached
  envelope on the spatial-filter path -- a falsified one makes =ogrinfo -spat=
  drop a feature that really intersects -- so an unverified byte layout would
  lose query results silently. V4 closed the plan: GeoParquet's =geo= =bbox=
  now switches to the spec's six-element 3D form
  (=[minx,miny,minz,maxx,maxy,maxz]= -- all mins then all maxes, *not* GPB's
  per-dimension pairing) whenever the data carries Z, the same length switch
  GDAL makes. The file-level =bbox= turned out to be load-bearing the same way
  the GPB envelope is, and on *mixed* 2D/3D input geosetta deliberately
  diverges from GDAL: GDAL promotes 2D geometry to Z=0 on write yet folds
  =minz= from the originally-3D features alone, leaving a bbox that misses the
  zeros it wrote. Geosetta does not promote, so folding real Zs only is exact
  here; the invariant -- the bbox Z range must cover every Z actually written
  -- is pinned by a test that would fail if a future writer started promoting.
- [[file:same-format-fidelity.org][same-format-fidelity.org]] :: A standing
  invariant -- *reading a format and writing the same format loses nothing* --
  and the one mechanism that delivers it without the IR swelling into a union
  of all nine spokes. A capability gap in the target excuses a drop; the target
  being the source's own format does not. Verified against GDAL 3.13.2, which
  already works this way: a hostile GeoJSON fixture (foreign members at both
  the collection *and* feature level, both =bbox=es, =id=, a nested property, an
  explicit null) survives =ogr2ogr= same-format intact, while a GeoPackage
  detour drops precisely the feature-level members -- an asymmetry that reveals
  the mechanism as an *opaque, driver-keyed* blob rather than semantic
  modelling. Adopts that shape: one =Native { format, payload }= field on
  =Feature=/=FeatureCollection=, replayed by a writer only when the tag matches
  itself, so adding a format touches only its own spoke and a native can never
  leak across a format change. Classifies natives as opaque / identity /
  *derived*, the last never replayed (a stale =bbox= is the =envelope.org=
  failure mode, where GDAL trusts the cache on the spatial-filter path).
  *Gates* [[file:same-format-output.org][same-format-output.org]] and inverts
  part of its scope. Carried three confirmed defects that become bugs the
  moment the rule is adopted -- the FlatGeobuf reader not restoring an omitted
  cell to null, the GeoPackage reader ignoring a =BOOLEAN= declaration its own
  writer emits correctly, and a =gpkg= → =gpkg= run destroying the container
  around the layers.

  *In progress, not scoping.* M1, M2 and M4 are done and M3 has four spokes of
  eight (GeoJSON, FlatGeobuf, GeoParquet, GeoPackage). The first two defects
  shipped with M4; the container one *now warns* and still destroys. Four more
  same-format losses were found and closed on 2026-08-21, none of them in the
  original list: a GeoPackage =REAL= column read back 32-bit, every unsigned
  width written as its same-width *signed* spelling, **every blob destroyed on
  read**, and 64-bit integers routed through an =f64=. What found them was a
  *recast matrix* -- every declared type through every declaring format,
  checked for types *and values*, against GDAL as a second opinion. Remaining:

- [[file:edit-composability.org][edit-composability.org]] :: Read a file, let
  *some other program* modify the feature collection, write it back -- the
  third seam in the family
  [[file:reproject-composability.org][reproject-composability.org]] started,
  where the external tool rewrites the whole collection rather than just its
  coordinates. The loop already runs (=geosetta f.fgb - --to geojson | jq ...
  | geosetta - out.fgb --from geojson --crs saved.crs=, verified end to end
  with the CRS surviving verbatim), so the plan is about what is wrong with
  it: *no transit format carries a full collection without loss*, and four of
  the losses are silent -- WKT drops every property, KML coerces them all to
  strings, FlatGeobuf drops null-valued ones outright, GeoPackage turns
  booleans into integers, none of them saying a word. The measured
  transit-fidelity matrix is the centrepiece, and its shape is the problem:
  the formats a stranger can edit are the lossy ones and the faithful ones are
  binary. The conclusion it does *not* support is "we need a new transit
  format" -- every silent loss in the two faithful rows traces to a geosetta
  defect over a wire that was already carrying the data (FGB keeps the column
  in its header and the reader will not restore an omitted cell to null;
  GeoParquet stored the CRS fine and =projjson_to_wkt= renders WKT1 by
  construction), so FlatGeobuf is one reader fix from carrying everything the
  IR models. What no format can raise is the IR's own ceiling -- feature =id=,
  collection =name= and the =bbox=es die at read time, before a transit is
  chosen. Also surfaces a live hazard -- in-place overwrite *through a pipe*
  works today, silently degraded a verbatim WKT2 CRS to WKT1, and is exempt by
  construction from the same-file guard
  [[file:same-format-output.org][same-format-output.org]] proposes.
  *Scoping only.*
