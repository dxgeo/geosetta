#+AUTHOR: Daniel Okuniewicz Jr.

* Reading Arbitrary GeoParquet (files from DuckDB / GDAL / Arrow / pyarrow)

** GOAL
Extend the round-trip reader (see
[[file:reverse-roundtrip.org][reverse-roundtrip.org]]) so Geosetta can read
GeoParquet produced by other tools, not just its own output. This is where the
Parquet format's real surface area lives; the round-trip reader is the skeleton
we hang these features on.

** PRECONDITION
The round-trip reader is done: thrift =CompactReader=, footer/schema parsing,
single-page PLAIN + RLE decode, snappy decompress, WKB decode, GeoJSON
serialize, and the =(Parquet, GeoJson)= pipeline arm all exist and are tested
(=src/parquet/reader.rs=).

** EMPIRICAL FINDINGS (DuckDB, the primary real-world target)
Measured by writing GeoParquet with DuckDB's =COPY ... (FORMAT PARQUET)= and
inspecting =parquet_metadata= / =parquet_file_metadata=. These drive the
priorities below — they are facts about what real files contain, not guesses.

- *Dictionary encoding is not optional.* Every =BYTE_ARRAY= column, *including
  the geometry (WKB) column*, is written as =PLAIN_DICTIONARY=. Numeric
  (=INT64=, =DOUBLE=) and =BOOLEAN= columns stay =PLAIN=. → We cannot read a
  DuckDB geometry column at all without dictionary support. This is milestone 1.
- *Multiple row groups appear immediately.* 200k rows produced *2 row groups*,
  split at DuckDB's default of 122,880 rows/group. Any file "at scale" has more
  than one. → Milestone 1 must iterate row groups, not assume one.
- *Codecs seen:* =SNAPPY= (default, already supported), =ZSTD=, and
  =UNCOMPRESSED= (already supported). =GZIP= not emitted by DuckDB but common
  from other writers.
- *=format_version= is 1* → data pages are V1 (same as ours). DuckDB does not
  emit =DATA_PAGE_V2= by default, so V2 is a later, lower-priority item.
- *=primary_column= may differ* — DuckDB names it =geom=, GeoParquet version
  =1.0.0=. The round-trip reader already reads =primary_column= dynamically, so
  this already works.
- *Current behavior on a DuckDB file:* the reader fails cleanly (no panic) with
  =invalid parquet: truncated varint= — it hits the dictionary index stream and
  can't parse it. The failure is safe but the message is unhelpful; see
  "Clean errors" below.

Local tooling note (superseded): =ogr2ogr=/GDAL and =cs2cs=/PROJ are now on
=PATH= in the dev environment (=pyarrow=/=geopandas= still aren't). GDAL
fixtures are now generated directly — see the covering-bbox milestone below,
which a real =ogr2ogr -f Parquet= fixture surfaced.

** MILESTONE 1 — dictionary encoding + multiple pages/row groups — *DONE*
Implemented in =src/parquet/reader.rs=. Geosetta now reads DuckDB's default
GeoParquet: a 200k-row, 2-row-group file with =PLAIN_DICTIONARY= on the string,
INT64, and geometry columns decodes to all 200k features with values matching
DuckDB (verified across the row-group boundary). =UNCOMPRESSED= files read too;
=ZSTD= now fails with a clear "unsupported compression codec ZSTD" rather than a
cryptic varint error. A committed fixture (=tests/fixtures/duckdb_dict.parquet=)
covers the dictionary paths for INT64 / string / geometry plus a PLAIN boolean.

Original scope, all landed:

*** 1a. Richer column-chunk metadata
=parse_column_meta= currently keeps =physical=, =codec=, =data_page_offset=,
and the leaf =name=. Add:
- =dictionary_page_offset= (=ColumnMetaData= field 11, optional): when present,
  the chunk *starts here*, before =data_page_offset=.
- =total_compressed_size= (field 7): bounds the byte range of the whole chunk,
  so page iteration knows where the chunk ends.
- =num_values= (field 5): total values in the chunk, so page iteration knows
  when it has consumed them all.
- =encodings= (field 2) is informational; the authoritative per-page encoding is
  in each =DataPageHeader=.

*** 1b. Multiple row groups
=parse_file_metadata= currently keeps only the first row group. Change =Meta= to
hold =Vec<RowGroup>= where =RowGroup { num_rows, columns: Vec<ColumnMeta> }=.
=read_geoparquet= decodes each row group and *concatenates* columns across
groups in order. Total rows = sum of per-group =num_rows= (cross-check against
=FileMetaData.num_rows=).

*** 1c. Page iteration within a chunk
Replace the single =decode_column= (one page at =data_page_offset=) with a loop
over the chunk's byte range =[chunk_start, chunk_start + total_compressed_size)=,
where =chunk_start= is =dictionary_page_offset= if set else =data_page_offset=:
- Parse each =PageHeader= (already have =parse_page_header=; extend it to also
  return =page_type= (field 1) and the =DataPageHeader= / =DictionaryPageHeader=
  fields: =num_values= and the value =encoding=).
- =DICTIONARY_PAGE= (type 2): decompress body, PLAIN-decode into a *typed
  dictionary* (=Vec<Vec<u8>>= for =BYTE_ARRAY=, =Vec<i64>=/=Vec<f64>= etc.).
  Keep it for the chunk's subsequent data pages.
- =DATA_PAGE= (type 0): decode body per its =encoding= (see 1d), appending to the
  chunk's running column until the chunk's =num_values= are consumed.

*** 1d. Value-encoding dispatch on data pages
The page body for a flat OPTIONAL column is =[u32 deflen][RLE def levels][values]=
(same framing the round-trip reader already parses; repetition levels are absent
when max rep level is 0). Dispatch on the data-page =encoding=:
- =PLAIN= (0): the existing =plain_*= decoders.
- =PLAIN_DICTIONARY= (2) or =RLE_DICTIONARY= (8): the values section is
  =[1 byte bit_width][RLE/bit-pack hybrid of dictionary indices]=. Decode the
  indices and map each through the chunk's dictionary.
  - *Reuse* =decode_levels(data, bit_width, count)= — it already handles the
    general RLE/bit-pack hybrid at arbitrary bit width and stops at =count=. The
    dictionary index stream has no 4-byte length prefix (it runs to the end of
    the values section), which is exactly how =decode_levels= consumes it.

*** 1e. General RLE/bit-pack hybrid — already done
The round-trip reader's =decode_levels= already decodes both RLE and bit-packed
runs at arbitrary bit width (it was written general on purpose). Milestone 1
reuses it verbatim for dictionary indices; no new bit-unpacking code needed.

*** 1f. Clean errors for the unsupported
Where a page uses an encoding/codec/page-type we don't implement, return a
specific =Error::Parquet= naming it (e.g. "unsupported page encoding
DELTA_BINARY_PACKED") instead of failing deep in a varint read. This turns the
current opaque =truncated varint= into an actionable message.

*** Milestone 1 test strategy
- Fixtures generated with DuckDB, committed small under =tests/fixtures/=:
  - a dictionary-encoded file (low-cardinality string + geometry column);
  - a multi-row-group file, forced small with =COPY ... (FORMAT PARQUET,
    ROW_GROUP_SIZE 4)= so a handful of rows spans several groups.
- Assert our reader's output matches DuckDB's own =read_parquet= of the same
  file (row count, per-column values, geometry decoded from WKB).
- Unit-test the dictionary index path: build a dictionary + =RLE_DICTIONARY=
  index stream by hand and assert the mapped values.

** LATER MILESTONES (evidence-ordered)

*** 2. ZSTD codec — *DONE*
Implemented from scratch (RFC 8878) in =src/compress/zstd.rs=: a decoder with
FSE (tANS) entropy decoding, Huffman literals (direct and FSE-compressed
weights, 1- and 4-stream), and the sequence machine (predefined/RLE/FSE tables,
repeat offsets). Verified against =zstd= CLI vectors (raw / RLE / Huffman /
structured, levels 1–19) and DuckDB's ZSTD GeoParquet — the 200k-row file
decodes with values matching across the row-group boundary. Committed fixture:
=tests/fixtures/duckdb_zstd.parquet=.

Provenance: independent implementation from the RFC, not derived from Meta's
=zstd= sources; the format is an open standard and libzstd itself is dual
BSD/GPLv2. The =zstd= CLI is used only as a test oracle. Documented in the
module header.

*** 3. GZIP codec — *DONE*
Implemented from scratch in =src/compress/gzip.rs=: RFC 1951 DEFLATE =inflate=
(stored / fixed / dynamic Huffman, canonical-code decoding, length/distance
matches) plus the RFC 1952 gzip container (also tolerant of bare zlib or raw
DEFLATE). Verified against Python =gzip= vectors (text / repetitive /
incompressible / small, levels 1–9) and DuckDB GZIP GeoParquet, including a 200k
multi-row-group file. Committed fixture: =tests/fixtures/duckdb_gzip.parquet=.

*** 3b. LZ4 codec — *DONE*
=LZ4_RAW= (codec 7, what DuckDB/Arrow emit) implemented from the LZ4 block spec
in =src/compress/lz4.rs= — a small LZ77 sequence decoder (token, variable
literal/match lengths, 2-byte offsets, overlapping copies), no entropy coding.
Verified against DuckDB LZ4 GeoParquet (200k rows) and a committed fixture
=tests/fixtures/duckdb_lz4.parquet=. The legacy Hadoop-framed =LZ4= (codec 5)
still errors cleanly; Brotli remains unimplemented.

*** 3c. Nested-schema definition levels + the GeoParquet covering-bbox column — *DONE*
=parse_file_metadata='s schema handling used to match a column chunk to its
schema definition *by bare leaf name*, reading only that one element's own
=repetition_type= — correct for a flat schema (DuckDB's default shape, which
is all this reader had real fixtures for), silently wrong for anything
nested: a leaf's true definition level is the count of OPTIONAL/REPEATED
*ancestors* down to and including itself, not just its own repetition type.

This was invisible until a real =ogr2ogr -f Parquet= fixture hit it: GDAL
3.13 / Arrow 25 writes a GeoParquet 1.1 =geometry_bbox= "covering" column —
a per-row bbox struct (=xmin=/=ymin=/=xmax=/=ymax=) alongside the WKB
geometry, a spatial-pruning optimization. Its leaves are REQUIRED *within*
the struct but the struct itself is OPTIONAL, so their true definition level
is 1, not 0; reading it as 0 made the reader skip a real, present
definition-level section entirely and start parsing dictionary indices 4
bytes into what was still level data — surfacing as
=invalid parquet: zero-length level run=, a confusing symptom of a schema
bug, not page corruption.

Fixed in =src/parquet/reader.rs=:
- =SchemaNode= now reads =num_children= (thrift field 5, previously
  unparsed), and =flatten_schema= walks the file's flat pre-order
  =SchemaElement= list as the tree it actually encodes — root first, each
  group immediately followed by its children — accumulating definition
  level through every ancestor rather than reading one element in
  isolation.
- =ColumnMeta= now carries its full schema =path= (not just the last
  segment), matched against =flatten_schema='s leaves by full path — a bare
  name isn't unique once nesting is in play (two different structs could
  each have an =xmin=).
- A leaf under a REPEATED ancestor (a genuinely list-valued column — a
  harder problem needing repetition levels this reader still doesn't parse)
  is flagged =unsupported_repeated= and rejected with a clear
  =Error::Parquet= naming the column, instead of attempting to decode and
  misparsing the same way the bbox column did.
- =covering_bbox_paths= reads the =geo= metadata's =columns.<col>.covering.bbox=
  key (GeoParquet 1.1) and excludes those columns from =properties=
  entirely — they're an index optimization, not real feature data, so they
  shouldn't surface as fake columns even once decodable.

Verified against a committed real fixture,
=tests/fixtures/gdal_covering_bbox.parquet= (=ogr2ogr -f Parquet= on a
3-point/2-property GeoJSON), plus unit tests for =flatten_schema= (flat
schema, nested-OPTIONAL-group inheritance, REPEATED detection) and
=covering_bbox_paths= in =parquet/reader.rs='s test module. Also fixed a
stale doc comment while in there: it claimed ZSTD/GZIP were unsupported
codecs, but =decompress= already handles them (only LZO, BROTLI, and
Hadoop-framed =LZ4= remain genuinely unimplemented).

*** 4. Additional physical / logical types — *PARTIAL*
Done:
- =INT32= (4-byte LE) and =FLOAT= (4-byte IEEE) widen into the i64 and f64
  columns respectively, surfacing as ordinary JSON numbers, in both PLAIN and
  dictionary encodings (fixture =tests/fixtures/duckdb_int32_float.parquet=).
- =DATE= (INT32 days) and =TIMESTAMP_MILLIS= / =TIMESTAMP_MICROS= (INT64) render
  as ISO 8601 strings, read from the schema's =converted_type= (DuckDB writes
  it, so no need to parse the =logicalType= union). Verified against DuckDB
  read-back including sub-second micros (fixture =tests/fixtures/duckdb_dates.parquet=).

Still to do: =INT96= (legacy timestamps), =FIXED_LEN_BYTE_ARRAY=, and =DECIMAL= /
=JSON= logical types. Writers that emit *only* =logicalType= (not the legacy
=converted_type=) would need the union parsed; DuckDB writes both.

*** 5. DATA_PAGE_V2
Distinct header: separate definition/repetition byte counts, an =is_compressed=
flag, and levels that are *not* compressed even when values are. Not emitted by
DuckDB default; handle or explicitly error until a real file needs it.

*** 6. Geometry variation
- WKB with Z / M / ZM (3D/4D) — extend =wkb::decode= and the =Geometry= model,
  or project to 2D with a documented note.
- The =geo= metadata may list multiple geometry columns or a non-CRS84 CRS —
  read =geo= rather than assuming defaults (ties into CRS handling on the write
  side too).
- Some writers use the newer Parquet native =GEOMETRY= logical type instead of
  the GeoParquet =geo= key/value convention — detect which is present.

*** 7. Nested/repeated (list-valued) columns — *SCOPING, not yet implemented*
The §3c fix taught the reader to compute definition levels correctly for any
column nested under an OPTIONAL group (=flatten_schema='s tree walk), and to
detect a REPEATED ancestor and reject it with a clear
=Error::Parquet("column \"...\" is a nested/repeated (list-valued) column,
which is not supported yet")= rather than attempt (and silently misparse) a
decode. This milestone is about actually *decoding* that case instead of
just detecting it.

**** Concrete example
A property that's an array — a GeoJSON feature with
="tags": ["park", "historic"]= — written by a tool that gives it a
native Parquet list type instead of falling back to a JSON string (which is
what Geosetta's own writer does for any array/object property value — see
=schema.rs='s =infer_columns=, used by every one of Geosetta's own format
writers). GDAL does this for its =StringList=/=IntegerList= OGR field types;
so does pandas/geopandas via Arrow's list type. Parquet represents a list
with its standard 3-level encoding:
#+begin_src text
optional group tags (LIST) {
  repeated group list {
    optional binary element (STRING);
  }
}
#+end_src
The middle =list= group is REPEATED: for a single row it can appear zero
times (empty list), once, or many times. That's a fundamentally different
shape from §3c's =geometry_bbox= (OPTIONAL — each row has *at most one*
value at that path); decoding a REPEATED column needs *repetition levels* —
a second value alongside each definition level saying "does this value
start a new row, or continue the same row's list as the previous value" —
which is how the reader would tell where one row's list ends and the next
row's begins within Parquet's flat, columnar stream of encoded values.
=parquet/reader.rs= doesn't parse repetition levels at all today; only
definition levels.

**** Where this connects to the write side (already solved, no new design needed)
Once a list's elements are decoded, they don't need a new representation of
their own — they slot into the IR's existing =JsonValue::Array= and flow
through the *same* universal fallback every array-valued property already
uses, regardless of format: =schema.rs='s =infer_columns= treats any
=JsonValue::Array=/=JsonValue::Object= property as JSON text (line ~71:
"Arrays/objects can only be represented as JSON text"), so it gets
serialized to a JSON string and written into whichever text-shaped column
each target format has (Shapefile =.dbf= =Character=, GeoPackage =TEXT=,
FlatGeobuf =ColumnType::String=, a CSV cell, another GeoParquet
=BYTE_ARRAY=). This is exactly what already happens today for a
GeoJSON-sourced array — =convert.rs='s test fixture has a feature with
="tags": ["a", "b"]=, and =read_recovers_geometry_and_properties= confirms
it comes back out as the string =["a", "b"]= after a GeoParquet round trip.
So this milestone is read-side only: decode the list into a =Vec<JsonValue>=
(=JsonValue::Array=), hand it to the property sink as one cell the same way
every other decoded value is, and the existing write path takes it from
there with zero changes. No format gets special-cased, including Shapefile —
it's already in the same "flatten to text" boat as every other format for
array-valued properties, list-typed source column or not.

**** What decoding needs (sketch, not yet designed in detail)
- Parse the repetition-level stream the same structural way
  =split_definition_levels=/=decode_levels= already parse definition
  levels (same RLE/bit-pack hybrid, a second bit-width derived from the
  schema's max *repetition* level rather than max *definition* level) —
  =flatten_schema= already has enough tree information to compute a max
  repetition level per leaf (count of REPEATED ancestors) alongside the
  max definition level it already computes; it just doesn't expose that
  number yet.
- Group consecutive values into per-row lists using the repetition levels
  (a repetition level of 0 marks the start of a new row's list; anything
  higher continues the current row's).
- Detect the standard 3-level list encoding structurally (a REPEATED group
  with exactly one child, itself either a leaf or a nested group) rather
  than only via the =LogicalType= annotation, since some writers only set
  the legacy =ConvertedType= =LIST= (=converted_type= 3) — mirrors how §4
  already prefers =converted_type= over parsing the =logicalType= union
  where both exist.
- Scope question: start with a list of scalars (covers the GDAL
  =StringList=/=IntegerList= case, the one with a real driver) and
  explicitly reject a list of structs/nested lists with a clear error,
  rather than trying to handle arbitrary nesting depth in the first pass.

**** Testing
- A real fixture: =ogr2ogr= writing a =StringList= (or =IntegerList=)
  OGR field to GeoParquet — same sourcing discipline as
  =gdal_covering_bbox.parquet=, committed small and real rather than
  hand-built. DuckDB can likely produce an equivalent list-typed column
  too (=LIST(VARCHAR)=), giving a second independent oracle.
- Unit tests for the repetition-level decode itself, mirroring
  =decode_levels_single_rle_run=/=decode_levels_bit_packed=: hand-built
  repetition-level streams for "all rows have exactly one element,"
  "some rows empty," and "some rows with several elements," checked
  against the expected row groupings directly (no full file needed).
- End-to-end: decode the fixture, confirm each row's =JsonValue::Array=
  matches the source data, then confirm the existing write path (§ "Where
  this connects to the write side" above) already turns it into the right
  JSON-string text in at least one non-GeoParquet format (Shapefile =.dbf=
  or GeoPackage =TEXT=) with *no new write-side code* — that's the
  milestone's actual completion bar, not just "the read decodes."

** ROBUSTNESS / VALIDATION
- Bounds-check every offset and length from the footer before slicing (the
  round-trip reader already does; keep it up as new offsets like
  =dictionary_page_offset= are added).
- Treat the file as untrusted input: no panics on malformed data; return
  =Error::Parquet= with context. Fuzz the thrift + page decoders.
- Optional statistics, page indexes, bloom filters: skip safely (=CompactReader::skip=
  already handles unknown fields).

** OPEN QUESTIONS
- *Resolved:* a fully dependency-free ZSTD decoder — implemented from scratch
  (§2 above); SNAPPY/UNCOMPRESSED/GZIP/ZSTD/LZ4_RAW are all supported, only
  LZO/BROTLI/Hadoop-framed-LZ4 remain.
- How faithfully must property *types* round-trip vs. being best-effort mapped
  onto GeoJSON's JSON value model (e.g. =INT32= → number, =TIMESTAMP= → string)?
- *Resolved, partially:* fixtures — GDAL is now available in the dev
  environment, and its output is committed as a small binary fixture
  (=tests/fixtures/gdal_covering_bbox.parquet=), matching the existing
  DuckDB-fixture convention rather than generating files in a test setup
  step. pyarrow still isn't available, so anything that needs it
  specifically (=DATA_PAGE_V2=, per §5) is unaffected.
